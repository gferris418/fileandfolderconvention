# Oracle Mapping — Placeholder

## Purpose

This profile exists to define how the provider-neutral EIOS File & Folder Convention can later be projected into Oracle-native content/storage repositories and controls without changing EIOS canonical identity, metadata, authorization, governance, lifecycle, or repository-binding semantics.

Candidate native constructs may include Oracle content repositories, folders, metadata/taxonomy facilities, and Oracle cloud storage/governance capabilities where appropriate.

## What this profile must eventually explain

- which Oracle construct represents each logical information level;
- how all seven EIOS information scopes are presented;
- how canonical metadata/taxonomy is mapped;
- how native identifiers relate to RepositoryBinding;
- how versioning/publication behavior is represented;
- how permissions, sharing, and access controls preserve or restrict EIOS authorization;
- how retention, legal hold/immutability, audit, events, search, and residency capabilities are declared;
- how binding roles, write modes, synchronization, and conflicts are handled;
- which limitations require compensating controls or make a repository ineligible.

## Status

This profile is intentionally not yet normative. Its current purpose is to reserve and define the implementation boundary. Detailed Oracle mapping will be developed only after the logical v1.0 convention is approved and must not alter the logical standard.
