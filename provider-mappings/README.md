# Provider Mappings

Provider mappings describe how the normative logical convention can be projected into a specific platform.

They are **not normative changes to the EIOS File & Folder Convention**.

Every provider mapping must state:

- native construct used for each logical level;
- naming/path constraints;
- metadata capabilities;
- permission and inheritance behavior;
- retention/records capabilities;
- external-sharing behavior;
- path/depth/character limitations;
- compensating controls;
- known non-conformities.

Provider mappings must never redefine canonical identity or silently broaden authorization.
