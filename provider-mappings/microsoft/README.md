# Microsoft Mapping — Placeholder

## Purpose

This profile exists to define how the provider-neutral EIOS File & Folder Convention can later be projected into Microsoft-native repositories and controls without changing EIOS canonical identity, metadata, authorization, governance, lifecycle, or repository-binding semantics.

Candidate native constructs include SharePoint sites, document libraries, folders, OneDrive where appropriate, Microsoft Graph identifiers, and Microsoft Purview governance capabilities.

## What this profile must eventually explain

- which Microsoft construct represents each logical information level;
- how all seven EIOS information scopes are presented;
- how canonical metadata/taxonomy is mapped;
- how native identifiers relate to RepositoryBinding;
- how versioning and publication are projected;
- how permissions/inheritance/external sharing preserve or restrict EIOS authorization;
- how retention, legal hold, immutability, classification/DLP, audit, events, and residency capabilities are declared;
- how binding roles, write modes, synchronization, and conflicts are handled;
- which limitations require compensating controls or make a repository ineligible.

## Status

This profile is intentionally not yet normative. Its current purpose is to reserve and define the implementation boundary. Detailed Microsoft mapping will be developed only after the logical v1.0 convention is approved and must not alter the logical standard.
