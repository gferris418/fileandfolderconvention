# Examples

## Purpose

Examples show how the convention can be applied using generic placeholder data. They are explanatory only and do not introduce normative business structures, canonical taxonomy terms, or provider requirements.

| Example | Purpose |
|---|---|
| `project-example.md` | Demonstrate how a Project navigation tree, controlled file name, and canonical `objectUID` remain separate concepts. |
| `tender-example.md` | Demonstrate how an Opportunity/Tender structure supports requirement, working, approval, submission, clarification, and award-transition navigation. |
| `document-numbering-example.md` | Demonstrate the distinction between canonical identity, immutable enterprise document number, revision label, display title, and filename. |

Examples should use placeholders and generic scenarios. They must not be treated as authoritative taxonomy, legal requirements, or implementation defaults where the normative standard says otherwise.
